## 1. What this file is, and what it is not

It is a **stand-in bed**, not game audio. The game cannot play any of these cues today: `pp_audio_music` looks for
`music/<asset>.ogg` and `datafiles/music/<asset>.ogg`, and the six delivered OGGs are mirrored to
`game/datafiles/streams/<asset>.ogg`, a path the music bus never reads (`game/scripts/pp_audio/pp_audio.gml`,
`knowledge/nodes/audio-routing.md` section 9, divergence 1). So the mp4's comment must keep saying the audio is a
stand-in; what it can now say as well is which cue it is.

It is built from the delivered files and nothing else. No cue was composed, recut, re-rendered or re-normalised
individually; each segment is a straight read of the file `data/audio.json` names, at the gain the game's bus
uses. No game file was touched: `data/audio.json` is read only, `tools/play_demo.py` (the testing lane's) is not
opened, and the one file added to `tools/` is `demo_bed.py`, this card's own builder. Nothing was uploaded.

### 8.5 Where the two new seconds come from

    handoff     = e08 at_second - marker_delay_steps / 60
                = 43.167 - 60/60
                = 42.167 s        the game's own "intro finished, starting the run in rm_pp_ship" line
    room load   = handoff + PP_FADE_STEPS / 60
                = 42.167 + 12/60
                = 42.367 s        the app machine's black frame, where the mode swaps

Both are computed by `tools/demo_bed.py` from the verify file and the run script, so a later take moves them
without anyone editing a number. Two honest limits, both named rather than rounded away:

- The capture reads the game log every 0.1 s (`time.sleep(0.1)`, `Replay.wait_marker`), so the recorded second
  can be up to 0.1 s after the line was printed. The derived 42.167 lands 0.117 s after the last crawl frame at
  42.05, which is that poll interval and nothing else.
- The derived room load is 42.367; the black frame is at 42.250 by measurement, so the derivation is 0.117 s
  late, for the same reason.

`PP-05` therefore enters at the handoff, 42.167, and its 0.500 s crossfade reaches full gain at 42.667, which is
0.184 s after the room is fully lit at 42.483. That is the point of the change: the cue change sits on the
picture's own transition instead of 0.950 s after it. `PP-01` stays ducked to the handoff, which is exactly where
`pp_title_step_intro` calls `pp_audio_unduck`.
