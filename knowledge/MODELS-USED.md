## The two models that are cited rather than answered

Both ids and the reason to use them come from entries in the field, and both are named here as the routing this entry has built rather than as calls a server has answered.

- **Muse Spark Open on Baseten.** Khet Saathi (rafatusa, 2026-10-27 06:30) runs the same agent loop on Muse Spark Open, served by Baseten, "for affordable rural-scale serving"; Ankita (krish) and paper-bro (Aero) name the same host. The model is 816B total and 42B active, needs about 700 GB of GPU memory at NVFP4, so it is hosted, never local: see `knowledge/OPEN-WEIGHTS-2026-10-26.md` and https://dev.meta.ai/docs/muse-spark-open. For this entry it is the rung a judge rerun can be served on, off the paid API, with the transcript cache as the fallback when no host is reachable.
- **Muse Voice Transcribe.** Khet Saathi names it as the voice input for Bangla and Hindi; the fight's `/hear` box asks for exactly the same thing in English, and `data/talk_live.json` already fixes the contract it must meet: 16000 Hz mono 16 bit PCM in, a transcript out, and a refusal rather than a guess when the recording is too short. The Meta rung is `meta_client.transcribe()`; the local whisper rung stays as the fallback, so a missing key costs a transcript and never the demo.

CukupAI (Ishab, 2026-10-26 16:04) is the other entry the plan cites for breadth: ML Kit on the device plus SAM 3.1 plus Llama 3.1, with near zero API overhead. It is why the cut in this repository runs from a recorded answer (the network is not needed to reproduce it) rather than from a live call at demo time.
