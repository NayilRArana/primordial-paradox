# Launching the built game, 2026-10-24

The crash Nayil hit was not a broken build. It was a launch without its data argument.

## What actually happens

`output\PrimordialParadox\PrimordialParadox.exe` is the GameMaker **runner**, and it takes the compiled data as a
flag:

```
PrimordialParadox.exe -game PrimordialParadox.win
```

Run with no argument, the runner asks for a file in an Open dialog, and when that dialog is dismissed or ignored it
falls back to reading **its own executable** as the game data. That is the error:

```
ERROR in action number 1
of Create Event for object <undefined>:
Error attempting to load wad file with unexpected size 7941704 szFORM 3
```

7,941,704 is the byte size of `PrimordialParadox.exe`, which is the proof that it was loading itself rather than the
game. This was mistakable for a corrupt `.win`, and I suspected exactly that first; the `.win` was fine both times.

The window titled "Open" is a Windows file dialog, class `#32770` with a `DirectUIHWND` tree. A real game window is
class `YYGameMakerYY`, titled "Primordial Paradox". Those two facts separate a launch from a stall in one read.

## What is fixed

- A desktop shortcut, `Primordial Paradox.lnk`, whose target carries `-game "<...>\PrimordialParadox.win"` and whose
  working directory is the build folder. Double-clicking it now starts the game; verified by reading the shortcut
  back and by the game window appearing.
- The runner is launched from `tools\pp_launch.py:start_game(exe, win, ...)`, which already passes `-game`; every
  capture tool goes through it. Anything that starts the exe directly must pass `-game` too, or it reproduces this.

## The build, measured today

Igor, `--config=Default -- Windows Compile`, wrote the data file and exited 0:

```
Saving IFF file... D:\AI Agent Automations\Shared\projects\primordial-paradox\output\PrimordialParadox\PrimordialParadox.win
Igor complete.
```

Note that `Compile` produces the data file only; the runner executable in the folder is the runtime's, not a
per-build artifact, which is why the exe's date never matches the build date and is not a sign of a stale build.

## Result

The game runs the current data: title screen, logo, and the menu with NEW GAME, CONTINUE, SETTINGS and QUIT.
