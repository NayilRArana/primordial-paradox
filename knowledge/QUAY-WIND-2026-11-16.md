## What was missing, and what now exists

The room had the hurricane **drawn** (`game/scripts/pp_storm/pp_storm.gml`: the eight step flash, the wind
gate, the WIND meter) and no sound of it. That gap is closed:

1. **`wind_quay`**, a genuine loop in `tools/sfx.py`. The 2A03 noise channel is the wind, and the loop is
   proved rather than faded: the APU's 15 bit LFSR repeats every 32767 clocks, so the file walks exactly one
   whole cycle of it (period 202 CPU cycles, 163091 samples, 3.698 s). Sample i reads clock
   `floor(i * 32767 / n)`, so the wrap is one more LFSR step, the same step every other pair of samples makes.
   Two layers out of that one stream (a 900 Hz low passed roar and its first difference as spray) and a gust of
   three sines whose periods divide the file, so the swell is part of the loop. Measured: peak -3.00 dBFS, rms
   -13.22 dBFS, seam step smaller than its largest internal step, spectral flatness well above a tone's.
2. **The wiring**, in `game/scripts/pp_audio/pp_audio.gml`. `pp_audio_wind_step` holds ONE looping instance
   (`audio_play_sound(_sound, PP_AUDIO_PRI_SFX, true, gain)`), started while `pp_storm_active` is true on the
   Town Quay and stopped when it is not, with its gain following `pp_storm_wind` (the complement of Morgan's
   mercy, 100 before the talk, 0 once the gate opens). The focus rule pauses and resumes it rather than
   restarting the storm. One log line on start, on stop and on each tenth of gain, so a headless run proves the
   wind played and not only that the room has weather.
3. **The demo cut**, in `tools/demo_music_bed.py`. `WIND_TABLE` lays the same delivered loop under every second
   the cut spends on the quay: S3 29.000 to 39.000, S4 39.000 to 78.000, S5 78.000 to 110.000 and the quay the
   spare reopens at S6 140.833 to 151.083, at 0.288 (0.9 of the game's own 0.32 wind level) under the 0.385
   music bed. The verify measures the wind in its own reference, at the loop offset the window has reached, and
   adds the control the presence has to pass: **no** correlation with the wind where no storm plays.

`python tools/event_audio_map.py --check` read `FAIL 29 problems`, and 26 of the 29 were

place of the old count: each fragment lands on exactly one site, every site is claimed by exactly one row, and
the shipped map cites the line the gml writes it on today. Measured on a scratch copy of the gml with 90 lines
inserted above the table: 39 sites before and after, all 38 rows resolve with 0 problems; the shipped map
against that shifted file reports 38 `re-run --build` rows, so the check still catches a stale map rather than
passing everything; and a map rebuilt against the shifted file reports 0 problems.

### The wind's seven lines, and the level a regeneration would have got wrong

Seven rows: `wind_started` (`ambience_start`), `wind_gain` and `wind_back_up` (`ambience_gain`),
`wind_ramping_out` (`ambience_stop`), `wind_stopped`, `wind_not_in_manifest`, `wind_no_channel` (`none`). Each
names the branch it waits on and is marked unobserved, because the loop was added after every log in the tree was
recorded.

The trap the reviewer named is closed at its source: `effect_gain` gave any id outside the play path the one-shot
effect level 0.9, so a bare `--build` would have recorded the wind at 0.9 with "pp_audio_sfx: the effect level",
three times the level the game plays. `AMBIENCE_CALL_SITE_IDS` gives the held ambience its own path read from
`PP_AUDIO_GAIN_WIND`: the row's gain is 0.32, the reason names `pp_audio_wind_step`, and `loop_played` is true
because it is the one effect the bus holds. `tests/test_event_audio_map.py` now parses the four playable effect
levels out of the gml instead of typing them, and pins the wind row to the ambience macro and away from the sfx
level.

Mutants, run in memory against the shipped map: wind gain set to 0.9 -> `wind_quay: gain 0.9 and the call sites
say 0.32`; a row whose wording no longer matches -> `no message site carries ...`; a message site with no row ->
`gml line 541 writes a PP audio: line with no row in the table`; table and map restored -> 0 problems.

The cost is measured rather than argued, and it is not this card's. With the take's mirror copy on disk and its
