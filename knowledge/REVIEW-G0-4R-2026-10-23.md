## F1, blocking: the refused SPARE press cannot be pressed, so the interruption never fires

`game/scripts/pp_battle_commands/pp_battle_commands.gml:38-41`: the SPARE entry is disabled whenever
`pp_battle_spare_allowed` is false. `game/scripts/pp_battle_director/pp_battle_director.gml:214` returns on a disabled
entry before `pp_battle_begin_action` is reached, so the interrupt branch at `:263` is dead code in play.

The numbers make it airtight: spare is accepted at hp <= 25 percent of 120, which is 30 hp or less; the interrupt gate
is hp <= 40 percent, which is 48 hp. Every hp in 31 to 48 with trust below 3 is a state where the entry is disabled, so
the only reachable SPARE outcomes are an accepted spare and a cursor note. The tests miss it because
`tests/test_prometheus_interrupt.py:433` (`press_spare`) and `tests/test_fight_endings.py` both resolve the press
without ever calling `pp_command_state`.

Required fix: keep the press reachable in the gate window, for example in `pp_command_state`'s spare case, refuse only
when both `pp_battle_spare_allowed` and `pp_battle_interrupt_ready` are false; and add a test that walks
`pp_command_state` -> the menu confirm -> `pp_battle_begin_action` instead of modelling the press in Python.

## F2, blocking: no caller plays the scene, and the player is asked to press a key the spec says not to press

`game/scripts/pp_app/pp_app.gml:376-389`: when the fight is finished the mode waits for `pp_pressed("confirm")`, then
clears the battle and calls `pp_overworld_battle_finished(..., _outcome)`. `game/scripts/pp_overworld/pp_overworld.gml:194-209`
handles `spare` and `kill` only; `interrupted` writes no flag and starts no scene. `pp_battle_interrupt_scene` is called
in one place, a debug line at `pp_battle_director.gml:707`.

Consequences: `met_prometheus` is never set (the scene that sets it is never run), `prometheus_interrupt` never plays,
and spec 18 section 4 step 4's "the caller continues with no press" is not what the build does. F1 and F2 also compound:
with F1 fixed and F2 not, the flag cannot be set, so the same SPARE press would fire the interruption again on the next
turn.

Required fix: capture the scene id before the battle is cleared and start that scene with no key press, through the
one scene door (`pp_overworld_start_scene`) or an equivalent; the `battle` command in a scene
(`pp_scene.gml:470-475`) currently discards `battle_done`, so a scene-launched Percy fight has the same hole. Add a test
that pins the caller, not only the row.
