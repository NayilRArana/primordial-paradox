# R7 GPU lane, measured on 2026-10-23 (card t_d1906a5b)

Follow-up to `knowledge/` plus card t_8079559f. That card painted the four R7 concepts with our own painter
and reported the GPU half as blocked. This is the GPU half, actually run.

## What ran, in order

1. **Client.** `kaggle` 2.2.5 installed into a private virtualenv under the worker's own workspace, never into a
   shared agent venv. `KAGGLE_API_TOKEN` (a `KGAT_` token, 37 characters, never printed, never read by our code)
   authenticates through the client's own loader as user `nayilarana`, and an authenticated read
   (`kernels_list`) answered, so the credential is live rather than merely present.
2. **Kernel.** `nayilarana/primordial-paradox-r7-gpu-concepts`, private, GPU on, internet on. Source committed at
   `tools/kaggle/r7_concepts/` so the run is reproducible. Five versions; the ones that mattered:
   v1 to v2 proved the pipeline could load SDXL but lost the LoRA to a torchao mismatch, v3 mounted SAM 3, v4
   fixed the SAM input shape, v5 is the run whose output is in `output/kaggle_r7/concepts_gpu/`.
3. **Hardware and stack of the accepted run:** Tesla T4, 15.6 GB, torch 2.11.0+cu128, python 3.13.15,
   diffusers from the Kaggle image, keras_hub 0.26.0. Run started 11:33Z, finished 11:37Z.
4. **Model.** `stabilityai/stable-diffusion-xl-base-1.0` at fp16 with `nerijs/pixel-art-xl` LoRA at weight 0.85,
   DPM++ multistep with Karras sigmas, 28 steps, guidance 6.5, one fixed seed per subject (70241 to 70244).
   640x640 rendered, then reduced to the frame the quantiser reads: 128x120 then nearest neighbour 2x to 256x240
   for scenes, and a corner-colour cutout reduced to 16x16 for the sprite. Every frame's sha256 is in
   `output/kaggle_r7/concepts_gpu/r7_manifest.json`.
5. **Meta image models: what they actually are.** Meta publishes no text to image generator on Kaggle Models or on
   Hugging Face. The `metaresearch` catalogue is `llama-2`, `llama-3`, `llama-3.1`, `llama-3.2`, `llama-3.2-vision`,
   `codellama`, `dinov2`, `imagebind`, `musicgen`, `segment-anything`, `segment-anything-2`, `segment-anything-2.1`.
   So "concept art from Meta image models" can only mean segmentation, never generation, and the frames above came
   from the best reachable image model instead. That is the honest reading of PLAN-WIN section 1 and the phrasing
   there should change.

## The measurement, and what it means

Run: `python tools/kaggle_r7.py --concepts output/kaggle_r7/concepts_gpu`. The painted lane report it replaces is
parked at `output/kaggle_r7/report_local_baseline.json` (same run, `report_local_baseline.md`).

| candidate | kind | model lane: score, mean dE | painted baseline: score, mean dE |
| --- | --- | --- | --- |
| quay_dusk_scene | scene | 100.0, 25.82 | 100.0, 3.57 |
| deck_night_scene | scene | 100.0, 34.26 | 100.0, 6.37 |
| wardroom_scene | scene | 100.0, 24.60 | 100.0, 10.25 |
| percy_deck_sprite | sprite | 88.9, 17.69 | 70.0, 49.30 |

The delta E limit is 10.00 for all four. Nothing model made is accepted, but the shape of the loss is the finding:

- **Scenes: the model costs 2.4x to 5.4x more colour error than our painter.** After per area quantisation a
  diffusion frame breaks none of the palette rules (100.0 score, 0 area fails, 0 palette count fails, 0 set
  member fails) yet loses far more of the colour the picture started with. A diffusion render is a continuous
  image wearing 2x2 blocks; it is not a limited palette drawing, and no amount of prompt wording fixed that.
- **The sprite flips the other way, and this is the useful result.** Our painter put Percy's coat outside the rows
  `battle_deck_night` can spend, so the baseline sprite scored 70.0 at 49.30. The model sprite scores 88.9 at
  17.69, still over the limit but nearly three times closer, because the model drew a figure whose colours happen
  to sit near one of the four rows. The sprite tile rule still fails once, so it is not shippable as is.
- **Conclusion for the pitch and for G0 scope:** the GPU lane is worth keeping for CHARACTER work, and it is not
  worth the round trip for background art at 256x240 with a 13 colour scene set. The cheap path for scenes stays
  our painter, or a human pixel artist.

## Segmentation with SAM, settled

`keras/sam3` mounted as a Kaggle model source at `/kaggle/input/models/keras/sam3/keras/sam3_pcs/1` and loaded
through `keras_hub.models.SAM3PromptableConceptImageSegmenter`. It runs: 200 queries per prompt, text prompts as
noun phrases ("wooden mast", "night sky", "naval captain"), masks cut to the frame.

**SAM 3.1 is not reachable and this is why.** On Hugging Face `facebook/sam3` is `gated: manual`, which needs a
click on a licence page that nobody in this lane can make. The only `sam3.1` on Kaggle Models is
`safebet1034/sam3-1`, a third party re-upload, and pulling someone's unvetted weights into the art lane is not a
trade worth making. So the segmenter used is SAM 3 itself, from the curated `keras/sam3` model.

**And it did not beat k means, so segmentation stayed deterministic k means.** Best confidence per prompt:

| frame | best prompt | best score | instances above 0.10 |
| --- | --- | --- | --- |
| quay_dusk_scene | sky | 0.1644 | 7 (sky), 12 (water) |
| quay_dusk_scene | wooden mast / wooden crate | 0.0151 / 0.0261 | 0 |
| deck_night_scene | night sky | 0.0913 | 0 |
| wardroom_scene | wall | 0.0896 | 0 |
| percy_deck_sprite | character | 0.0028 | 0 |

Nothing reaches 0.25, let alone the model's own 0.5 confidence. A 30M parameter promptable concept segmenter is
built for photographs; a 256x240 frame of flat 2x2 blocks gives it nothing to key on. The two masks it did return
(quay sky and water, at the 0.10 floor) are saved beside the frames as `*_sam_sky.png` and `*_sam_water.png` for
the record, and they are not used by any rule. `tools/kaggle_r7.py`'s `segment()` is still the shipped segmenter.

## What is still unproven

- No human has looked at these four frames. The score is rule conformance and the delta E is colour loss; neither
  is beauty. The eye critic still has to say whether the quay frame reads as a dusk quay.
- One GPU, one seed per subject, one prompt each. A different seed can move the delta E by several points; nobody
  has measured that spread.
- The sprite cutout is a corner colour test, not a matte. If the model ever paints the figure into the corners the
  cutout goes wrong silently, which is why the frame falls back to fully opaque when it keeps fewer than 24 pixels.
- `output/` is gitignored, so the frames and the log of the accepted run live on disk only. The kernel is
  reproducible from `tools/kaggle/r7_concepts/`, but re-running it costs GPU minutes and will not reproduce the
  same bytes if the diffusers version on the image changes.

## Provenance

Studied: this repository's own R7 lane (`tools/kaggle_r7.py`, `tools/quantize_concept.py`,
`tools/palette_synergy.py`, `tools/nes_check.py`, `tools/scene_palette_set.py`, `tests/test_kaggle_r7.py`), the
public model cards for `stabilityai/stable-diffusion-xl-base-1.0`, `nerijs/pixel-art-xl`, `keras/sam3` and
`metaresearch/segment-anything-2.1`, the `keras_hub` SAM 3 preset source, and the Kaggle API client's own
documentation strings. No decompiled material was read for this card and no expression from any game is in it.

Mechanics learned: two. One, a generation lane and a measurement lane have to be separate artifacts with separate
provenance, because the moment a tool both paints and grades, a good score stops telling you whose work it is; the
fix is a concept source field and a manifest with a sha256 per frame, not a comment. Two, promptable segmentation
fails on stylised low resolution art for a measurable reason (confidence) rather than a mysterious one, so the
right move is to record the score distribution and keep the deterministic segmenter, instead of tuning thresholds
until something appears.

Our implementation differs by: mounting the segmenter as a read only Kaggle model source and loading the preset by
path, because kagglehub refuses to attach a model from a non interactive session (measured, run 2); recording the
EFFECTIVE LoRA after the load attempt rather than the requested one, because the Kaggle image's torchao breaks
diffusers' peft bridge and a run that silently drops the LoRA must not claim it used it; reducing the frame with
nearest neighbour so no colour enters the concept that the model did not draw; and keeping the painted report as a
parked baseline file that a later model run cannot overwrite.
