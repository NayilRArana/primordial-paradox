## The three labels, and what makes each one checkable

| label | the value is | the receipt carries |
| --- | --- | --- |
| measured | read out of a committed file, or counted from its own rows | file path, locator inside it, sha256 of the file |
| computed | arithmetic over measured numbers | the formula, plus the same file and sha256 |
| inferred | not in any file; read off a plan or a shot table | the file, the section, and a sentence saying it is a reading |

## Where the labels land, and who reads them

1. `tools/receipts.py` builds the block and appends one ledger line per number, deduplicated on
   (name, label, value, source, sha256), so a second run over the same inputs adds nothing.
2. `tools/play_demo.py` calls it inside `verify_video`, so every take's `output/demo/<take>_verify.json`
   carries `meta_numbers`. A build whose numbers cannot be vouched for writes `meta_numbers: []` plus
   `meta_numbers_why` instead of printing an unbacked number.
3. `tools/judge_panel.py` reads the block into `script_facts` and `measured_lines`, so the panel is shown
   `Labelled Meta number: <name> is <value>, labelled <label>, receipt <id>` for each one, and says so when a
   capture labels nothing.
4. `tools/check_receipts.py` is the verifier: it re-reads the block, resolves every receipt id in the ledger,
   compares name, label and value, re-hashes each source, and exits 1 on every fault it finds, all of them
   named at once.

## What this does not prove, stated plainly

- The labels say where a number comes from; they do not make the number good. A bake with 10 fallback rows
  still shows 10 fallback rows, labelled and receipted.
- `meta.talk_turns_onscreen` is a plan, not a measurement of a video, and it is labelled inferred for that
  reason. A capture that showed two turns would still carry the planned 3 until a per-take transcript count
  exists; nothing in this card builds one.
- The badge and the bake lines are proven on a still frame from `output/judge_frames` through
  `tools/demo_overlay.py --check`, not on a freshly recorded capture.
