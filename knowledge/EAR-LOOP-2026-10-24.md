## 3. What this file does not say

- The judge is not the judge in `knowledge/EAR-GATE-2026-10-23.md`. That gate ran entirely on `gemini-3.5-flash-lite`; a run here that falls through to `gemini-3.5-flash` is a different listener with a 14 point swing on the ship master already measured in that file. The `model` column is the only thing that makes two rows comparable, which is why it is a column and not a footnote.
- The ear misnames channels and miscounts bars. It hears the mix, not the score. A score here is a queue position, not a verdict.
- Scores are per cue and inline (every cue is under the 15 MB inline limit), so one cue is one call and a rotation cannot split a single cue across two models. A cue that is too long for one call is chunked by `ear_critic.py`, and that is the case where one verdict can be mixed; the ledger records the model of every chunk.

## 4. How to check this file

- Order: `python tools/ear_loop.py --dry-run` prints the order, the files and the state without sending anything.
- Rotation: `python tools/ear_loop.py --self-check` simulates a 429 on the first model and proves the run still scores all four cues, with no network and no key.
- Rows: `python tools/ear_loop.py --json` reprints the last run as JSON, and `data/ear_ledger.csv` holds one row per call with the model that made it.
- Dashes: this file carries no em dash, en dash, figure dash or horizontal bar; the tool rewrites long dashes in the model's own text before it writes them here.
