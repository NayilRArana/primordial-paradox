## 2026-10-25, PP-BOARDING v3 (t_329400a4)

1. **A dissonance device written in the lead costs hook meter points; the same device in the guide
   voice costs none.** `tools/hook_score.py` reads only the melody track (`vrc6 pulse a`), so any
   note added to the lead changes motif coverage and return count. Measured on one cue: the chromatic
   neighbour plus the 9-8 suspension in the lead read 85, then 95, then 96 of 100 with 3 returns;
   moved into `vrc6 pulse b`, the same cue reads 100 of 100 with 4 returns and both devices still
   audible. DIS-02, DIS-06 and DIS-05 all name the pad or countermelody as permitted voices, so the
   guide is the cheap place for a device.
2. **A cue's statement bars are the meter's spine: never repurpose one for colour.** v2 states the
   hook at bars 1, 3, 5 and 7. This build first replaced bar 8 with a different deck figure and lost
   a return, which is 12 points and 20 points of coverage on its own. Read `LEAD_BARS` and count the
   statements before editing any bar of a cue that already reads 100.
3. **Read a key from the Windows user environment without ever echoing it.** `reg query
   HKCU\Environment` prints its values with no `=`, so a redaction pattern built for `NAME=value`
   leaks every value in the listing (it happened on 2026-10-25: GEMINI_API_KEY, PINE_SANDBOX_API_KEY
   and KAGGLE_API_TOKEN were printed into a session log). Use
   `reg query 'HKCU\Environment' /v NAME | sed -n 's/.*REG_SZ[[:space:]]*//p' | tr -d '\r'` into a
   variable, print only `${#K}`, and never list the whole key without a name filter.
4. **`cp` a script before a sed trial, then restore from the copy, not from memory.** The hook meter
   trials on this cue needed four builds in five minutes; the copy made each revert one command.
5. **State the threshold a check uses.** The one shot's last half second is not digital silence in
   this renderer: it measures -37 dBFS in a 0.25 s tail window. The check now says "below -30 dBFS"
   and prints the number instead of claiming silence.
